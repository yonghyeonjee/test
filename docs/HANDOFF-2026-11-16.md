## 5. Cloudflare 계획

목적: 요청을 서버 한 대가 다 받는 구조를 바꾼다. 봇이 몰려도 Cloudflare 사본으로 끝나게 하고, 서버가 잠깐 흔들려도 구글봇이 오류 화면(→ NOINDEX 판정)을 받지 않게. 색인 자체를 고치는 일은 아니다.

무료 요금제는 **도메인 전체의 네임서버**를 Cloudflare 로 옮겨야 한다(하위 도메인만 따로 맡기는 CNAME 방식은 유료).

| 안 | 방법 | 장점 | 단점 |
|---|---|---|---|
| **A. knowhow-it.com 을 통째로 Cloudflare 로 (권함)** | Cloudflare 에 도메인 추가 → 가비아 DNS 기록을 모두 옮겼는지 확인 → Porkbun 에서 네임서버 2개 교체 | 주소가 그대로라 SEO 손실 없음 | 워드프레스(가비아 호스팅) 기록·메일(MX)을 빠짐없이 옮겨야 함. 워드프레스 기록은 '프록시 끔(DNS only)'으로 두면 지금과 같음 |
| B. 새 도메인 | 새 도메인을 Cloudflare 에 두고 jiwon 을 옮김 | 워드프레스와 완전히 분리 | 주소가 바뀜. 옛 주소에서 301 을 계속 줘야 하고, 서치 콘솔 주소 변경·사이트맵·ChatGPT 가 아는 링크를 다시 쌓아야 함 |

B 메모: 지금은 색인이 거의 없어 옮기는 손해가 가장 작은 때이긴 하다. 그래도 ChatGPT 유입이 옛 주소 공고 쪽으로 들어오니 301 은 영구로 둔다.

A 순서:

| 단계 | 누가 | 메모 |
|---|---|---|
| 1. Cloudflare 가입, `knowhow-it.com` 추가, 자동으로 읽어 온 DNS 기록을 가비아 관리 화면과 한 줄씩 대조 | 사용자 | 뿌리(@)·www·MX·TXT(메일 인증)·`jiwon` |
| 2. Porkbun 에서 네임서버를 Cloudflare 가 준 2개로 교체 | 사용자 | 적용까지 몇 시간. 그동안 두 곳 다 같은 답을 주므로 끊김 없음 |
| 3. 서버: Caddy `trusted_proxies` 에 Cloudflare 대역, 접속 기록·fail2ban 이 `CF-Connecting-IP` 를 읽게. SSL 은 Full(strict) | Claude | PR 하나. 2단계 전에 준비해 둔다 |
| 4. 첫 주: 정적 파일 캐시 + Bot Fight Mode 만. HTML 캐시는 끔 | 함께 | 기존 Caddy 규칙(@nolang 등)과 겹치는지 확인 |
| 5. 둘째 주: 허브·상세 HTML 을 짧게(10분부터) 캐시. CPU 가 넉넉하면 Lightsail 1GB($7)로 되돌릴지 판단 | 함께 | 되돌릴 때도 스냅샷으로 새로 만들고 고정 IP 이동 |

주의: Cloudflare 를 거치면 서버가 보는 IP 가 전부 Cloudflare 것이 된다. 3단계 없이 2단계를 하면 fail2ban 이 Cloudflare 를 막아 사이트가 죽을 수 있다.
